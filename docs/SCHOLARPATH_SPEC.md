## 1. Non-negotiable rules (set by the owner)

These override everything else. Check every change against them.

1. **Never invent anything academic.** No made-up findings, statistics, references, DOIs, IDs or page numbers. Unknown values become clearly labelled placeholders. Claude prompts in the app say this explicitly.
2. **Never delete or move a word of the original paper.** When a PDF is read, every word of every paragraph must appear, in its own paragraph, in order.
3. **A paragraph is one block.** If a figure or table interrupts a paragraph (even mid-sentence), the paragraph is still read as one block and the figure is placed **after** the whole paragraph.
4. **Figures and tables are not part of the reading.** In the Paper Reader they are not simplified, translated, summarised or read aloud. A picture of each is shown where it sits, with a button to **Figure Lab**, where it is explained and critiqued.
5. **Distinguish the authors' words from the student's evaluation** ("The authors report…" vs "In my assessment…").
6. **Examples are always labelled** "Example" or "Demo", and illustrative content is never presented as a real paper.
7. **Every generated output has a Copy button.** Everything works on a phone. Light and dark mode. No login. Everything is saved in the browser.
8. **Claude's output is always marked** ("by Claude — check it") and the user is reminded to verify it against the paper.
9. **Nothing is marked as checked or prepared unless it really is** (Part 4). A verification item counts only when it was checked on the current documents; a professor question counts as prepared only after the student has answered it. The original paper is the source of truth, a contradiction is never resolved silently, and the documents are never called fully consistent before the complete comparison is done (see 5.9).

## 3. Architecture

| Concern | How |
|---|---|
| Structure | One `index.html`: CSS, then markup (the sidebar `aside.side`, the header with the breadcrumb, one `<section class="panel">` per tab, the previous/next bar), then one script in an IIFE. | Office files | Part 4 reads `.docx` and `.pptx` itself: a small zip reader (`readZip`, using the browser's `DecompressionStream('deflate-raw')`) and `DOMParser`. Corrected copies are re-zipped with `zipStore` (stored, uncompressed). |
| PDFs | **pdf.js 3.11.174**, loaded from `vendor/pdfjs/` and falling back to cdnjs. Text is extracted in the browser; nothing is uploaded. |
| Claude (AI) | Only on the published claude.ai page: `window.claude.use('sample')`, using the **viewer's own Claude account** (consent is asked on the first call). In the plain file there is no AI; every AI feature has a manual alternative. |
| Downloads | On claude.ai: `window.claude.use('downloads')` (the viewer confirms each save). Elsewhere: a normal download link. |
| Published capabilities | `{"sample": {"images": true}, "downloads": true}`. Publish `index.html` with `vendor/pdfjs/pdf.min.js` and `vendor/pdfjs/pdf.worker.min.js` as supporting files. |
| Speech | The voices built into the viewer's device and browser (`speechSynthesis`, the Web Speech API): free, no account, nothing uploaded. ScholarPath has no voices of its own and no paid voice service (see 5.3). The app does **not** use browser pause and resume; it tracks its own position. |

## 4. How the app is organised: four parts

Since 12 October 2026 the app is presented as a **journey**, in the order the owner works (her request: *first writing a research paper and everything that helps, second building a critique, last the presentation*). Part 4 — the final verification (4.1) and the professor-questions defence preparation (4.2) — was added the same day as a permanent quality-control and preparation step.

| Part | Steps (in order) | Tab used |
|---|---|---|
| **Dashboard** | *Your Research Workspace*: continue researching, library, recent activity, the four research tools with every step and its progress | `start` |
| **1 · Write a paper** | 1.1 Writing path → 1.2 Find literature → 1.3 Ideas & reading list → 1.4 Figures & tables | `write`, `hub`, `ideas`, `figlab` (build mode) |
| **2 · Critique a paper** | 2.1 Read the paper → 2.2 Explain the figures → 2.3 Write the critique → 2.4 Trace your evidence | `reader` (paragraphs), `figlab` (explain mode), `critique`, `evidence` |
| **3 · Present** | 3.1 Build the slides → 3.2 Questions about the paper | `present`, `reader` (questions view) |
| **4 · Verify & defend** | 4.1 Final verification & consistency → 4.2 Professor questions & defense | `verify`, `defend` |
| **My Progress** | Overview, backup and restore | `progress` |

- **Navigation (since 13 Oct 2026):** a dark slate **sidebar** — Workspace (Dashboard, My Progress), then the four parts as groups with their numbered steps (1.1 … 4.2). The current part is open; the others fold (their state is remembered). The sidebar collapses from 248 px to a 72 px icon rail (button at the top, remembered); below 1024 px it is a drawer opened from the header's menu button (Escape or the backdrop closes it). The **header** (72 px) shows the breadcrumb *Part 2 · Critique a paper › 2.1 Read the paper* (shortened with … before it reaches the round logo), a **Full screen** button (the browser's Fullscreen API; shown only where the browser allows it — not on iPhone, and not inside a frame that blocks it, where F11 or Control + Command + F still work) and the theme button, so pages no longer repeat an eyebrow. **Previous / Next** buttons at the bottom of every step still lead through the whole journey. Each part remembers its last open step.
- **Addresses:** `#start`, `#writing/1` … `#writing/4`, `#critiquing/1` … `/4`, `#presenting/1` … `/2`, `#verifying/1` … `/2`, `#progress`. Old addresses (`#reader`, `#figlab`, `#critique`, …) still work and are rewritten.
- **Writing path → helpful tools:** each writing step links to the steps that help with it (e.g. *Find the gap* → Find literature, Read a key paper in simple English; *Results* → Build your figures).
- **Figure Lab** has no mode switch any more: step 1.4 opens build mode and step 2.2 opens explain mode, each with a link to the other.
- **Code:** `PARTS` defines parts and steps; `goStep(part, i)` opens a step; `showTab(tab)` (used throughout) finds the matching step with `stepFor`. `route()` reads the address. `renderTabs()` draws the sidebar and the breadcrumb; `applySide()` / `sideDrawer()` handle collapsing and the drawer (`S.ui.side`, `S.ui.navOpen`). The header is sticky and `--hdr` holds its height for sticky panels. `document.body.dataset.tab` names the open tab (the reader uses the full width).
- **Dashboard (`RENDER.start`):** *Continue researching* (the open paper, its paragraphs, figures and languages, simple versions written, Open the paper / Continue reading, Back to the last step, Listen), *Next in Part …* (the following steps with their status), **Library** (the Paper Reader's papers with coloured initials; Upload PDF / Paste text), **Progress summary** (four real counts, each opening its step), **This week** (the last seven days with the steps opened on each, from the log in `S.activity`: the steps you open and the papers you add, at most 150 entries, kept in this browser), **Research tools** (the four parts with every step and an honest status line from `startStatus()`).

## 5. Features, by tab

(Sections 5.1–5.8 describe the tabs; see section 4 for where each appears in the journey.)

### 5.1 Resource Hub (step 1.2)
- Cards for IEEE Xplore, Google Scholar, Scopus, Web of Science, ACM DL, ScienceDirect, SpringerLink, arXiv, Semantic Scholar and ResearchGate, each with a one-line "best for".
- **Search builder:** database + keywords + optional "from year" → a search link (Copy / Open). Web of Science cannot take a link, so it opens the search page and copies the query. arXiv, ResearchGate and WoS ignore the year (the user is told).
- Search tips: Boolean operators, quotation marks, date filters, field search, snowballing, search log.

### 5.2 Idea Organizer (step 1.3)
- Idea cards: title, research question, keywords, tags, status (Idea / Exploring / Drafting / Done). Filter by status and tag.
- Reading list: title, authors, year, venue, link/DOI (a bare DOI becomes a doi.org link), one-line takeaway, linked idea.
- Example: one idea (Arabic-language fairness in GenAI tutors) and two real papers (*Gender Shades*, 2018; *Stochastic Parrots*, 2021).

### 5.3 Paper Reader (steps 2.1 and 3.2)
**Input:** upload a PDF, or paste text. Each paper keeps its own notes and chats. Title is taken from page 1 (largest font).

**PDF → paragraphs (the hardest part; follow rules 2–4).** `pdfPageLines` builds lines with positions, then `pdfToParagraphs`:
- removes running headers and footers (identical lines **at a page edge** on 2–3+ pages) and page numbers;
- finds figure and table captions (`findFiguresOnPage`: "Fig. 3.", "Figure 3:", "TABLE II", "Table 2."), computes each figure's area (`figRegion`), and leaves out the caption plus the figure's own labels and cells — **but never a line that looks like body text** (body font size with ≥ 3 words, or a short line right next to body text);
- breaks paragraphs on: more vertical space than the page's measured line spacing (×1.3), a first-line indent, or a short last line ending a sentence. Across a **new page, new column or figure**, a paragraph continues unless a real paragraph start is seen (indent, in indented papers; otherwise a short previous line plus a capital letter);
- treats a line as a heading only if it looks like one (capital or number, short, standing alone);
- keeps hyphens at line ends unless the joined word occurs elsewhere in the paper ("twelve-week" stays, "evalu-ation" → "evaluation");
- joins short fragments (< 25 words) to the paragraph they continue (no full stop, starts lower case, or a figure in between), otherwise to the next one;
- places each figure **after the paragraph** in which it was met, as a `kind:'figure'` item with a cropped picture;
- stops at "References".

**Layout: three reading modes (redesigned 13 Oct 2026 at the owner's request: "the paper must remain the centre of the experience").** A slim **workspace bar** under the header (sticky on tablets and desktops) holds, in this order: the outline button, the paper, the **reading mode** — **Read · Study · Compare** (how the paper is shown; navy when chosen) — the **version** — **Original · Simple English · Arabic** (which text is shown and read aloud; white chip when chosen; in Compare: *Original vs Simple English | Arabic*), a **Study panel** button (wherever the panel is not already beside the paper) and ⋯ (Upload a PDF, Paste text, Idea flow, Presentation questions, Delete). Reading mode and version are separate controls and never mixed.
- **Read** — the paper alone, using the whole width. Selecting a paragraph highlights it and shows a small **toolbar** under it (¶, page, section · Explain · Translate · Notes · Ask Claude · Listen · ⋯); it stays in view while the paragraph is on screen. The tools open the **study panel as a drawer**: on wide screens the paper moves aside for it (nothing is covered); on narrower ones it slides over a dimmed paper. × or Escape closes it.
- **Study** — outline (optional) · paper · study panel beside the paper (from 900 px of reader width; a drawer below that). Selecting a paragraph updates the panel and keeps its tab; ‹ › in the panel move to the previous / next paragraph.
- **Compare** — the original and the chosen version side by side, each column scrolling on its own, with ¶ numbers in both. **Keep the columns in step** (on by default) keeps them aligned **paragraph by paragraph**, not pixel by pixel, so a short simple version never drags a long original; it can be switched off. Choosing a paragraph in either column selects it in both and brings its partner level. A paragraph without that version says so ("No simple version yet. Add one"), the Arabic column is right-to-left, figures appear only on the original side, and the columns can scroll past their end so any paragraph can be lined up at the top. On phones Compare shows each paragraph with its version underneath.
- **Your place is kept:** changing mode, version or comparison keeps the paragraph you were reading at the same spot, the selected paragraph, the panel tab, notes and progress; read-aloud continues while you switch. The mode, the outline per mode, the comparison and "keep in step" are remembered (`S.reader.layout`, `ol`, `cmpWith`, `cmpSync`).
- **Width for the paper:** on the reader page the app's sidebar starts as icons only (`S.ui.sideReader`, its own choice, so other pages keep theirs). The outline docks beside the paper when there is room (Read from 1000 px of reader width, Study and Compare from 1180 px) and otherwise slides in over the paper.

**The paper:** one continuous document, not a stack of cards — the reading serif *Source Serif 4* at 18 px / 1.75 in a column of at most 700 px, the paper's own section headings, a thin "Page N" rule where a new PDF page starts, ¶ numbers in the left margin (each is a button that selects its paragraph — the keyboard route), figures and tables as pictures with their caption and **Explain it in Figure Lab** (never read aloud; it opens the figure there with its picture, the sentences that cite it and the abstract, and Figure Lab has *Back to this figure in the Paper Reader*). The **title page** (title, authors, journal, DOI: the paragraphs marked *front*) is folded into one line, *Title page and publication details*, with every word kept. The selected paragraph has a soft blue background and a blue bar in the margin; the paragraph being read aloud a navy bar and the sentence highlighted.

**The outline** is built only from the paper itself (no invented sections): Title page, then each section with its ¶ range and page; sections with figures or tables show a count that unfolds them; search in the paper (original, simple and Arabic text); the section you are reading is highlighted as you scroll; **Reading progress** shows how far you have read, how many paragraphs have a simple version and an Arabic translation. It can be hidden in every mode.

**The study panel** (Explain · Arabic · Notes · Ask Claude · Paper) for the selected paragraph, with no large empty boxes — a missing part is one line with its buttons:
1. **Explain** — the Simple English version (editable; by Claude, the demo or the student), the main idea (shown; edited in Notes), key terms, **Explain in more depth** (asks Claude in the paragraph's chat; only on the published page), and Listen (Original, Simple, Arabic, Whole section).
2. **Arabic** — the Arabic translation (Claude or typed; the English never changes), vowel marks for listening, Listen in Arabic, and an **Explanation in Arabic** with a list of **key terms in English and Arabic** (Claude, marked "by Claude — check it", with Copy; told to explain only what the paragraph says).
3. **Notes** — main idea in my words, **My notes**, **Important concepts** (typed, or *Add the words I selected*; highlighted in the paragraph with the CSS Custom Highlight API, so not a character of the text changes), memory hook, and the link to an earlier paragraph; "Saved in this browser · time". Notes and concepts go into *Copy reading notes* and survive *Merge with next paragraph*.
4. **Ask Claude** — the paragraph's chat. Claude now also gets the rest of the paragraph's section and the start of the paper, and is told not to repeat what it already explained.
5. **Paper** — where the paragraph is: ¶ (of the total), section and page (the PDF's own page; "Not known" for pasted text — never invented), *Show in the paper*, *Copy reference*, the original paragraph word for word, the paragraphs before and after; then the whole-paper tools (simple versions, Simplify / Translate the rest, Copy reading notes, Use in Critique, Trace my evidence, the whole-paper chat).
Every generated text in the panel has a Copy button. When read-aloud moves to a new paragraph, the panel follows it (unless you are typing in it).

**Views:** the paper (in the three modes), **Idea flow** (⋯ menu: chain of main ideas and links, with figure markers; copyable reading notes) and **Presentation questions** (⋯ menu, and step 3.2: *You ask the class*, *The professor may ask you* with answer tips and paragraph links, *Colleagues may ask you*). Both have *Back to the paper*. Without Claude, sensible starter questions are shown.

**Read aloud** (rebuilt 12 Oct 2026 after the owner found the voices robotic, especially Arabic):
- **Provider:** the device's own voices. ScholarPath ranks them by quality — *Natural* (neural: Edge "Online (Natural)", Apple "Enhanced/Premium", Siri, WaveNet…), *Good* (online, e.g. Chrome's Google voices), *Standard*, *Basic* (often robotic) — and always prefers the most natural one. Edge's broken "undefined" voices (Edge 150 bug) are hidden.
- **Honest accents and regions:** English American (US), British (UK), Australian (AU), Canadian (CA), each offered **only** when the device has a voice whose own language tag is en-US / en-GB / en-AU / en-CA; otherwise "Not available on this device". Arabic: **Modern Standard Arabic is the default**; voices are grouped by the speaker's country (Gulf, Levantine, Egyptian, other) with the honest note that every Arabic voice reads what is written (a translation in الفصحى is read in الفصحى) — no dialect is imitated. **Pitch is never changed** (the old "adjust the pitch for a missing gender" was removed).
- **Voices & accents dialog:** every voice with its quality, woman/man, full system name and language; **Preview** (an academic English sample; an MSA sample with vowel marks; a mixed Arabic sentence with *Machine Learning* and *Facial Recognition Technology*); **Use**; "best voice" per accent or region; woman/man preference for automatic choice; a device-specific tip for getting natural voices (Edge, iPhone/iPad, Mac, Android, Windows).
- **The spoken copy (the written text never changes):** sentences are not split after *et al.*, *e.g.*, *Fig.*, initials or decimals, and long ones are split at ; : , rather than mid-phrase; abbreviations (e.g., i.e., Fig., p./pp., vs.), statistics (p < .05, M, SD, SE, df, 95% CI, R², χ², ±, ≤, Greek letters), ranges, links/DOIs and vowel-less acronyms (NLP → "N L P") are said in words; numeric citations [12] are skipped by default (or read as "reference 12"); Arabic tatweel is ignored and PDF presentation-form letters are normalised. A **personal pronunciation list** (written → say as, English/Arabic/both, with Try). Positions are mapped back to the written text, so highlighting and the exact-word bookmark still work.
- **Bilingual reading:** each sentence is split into English and Arabic runs; English terms in Arabic text are read by the English voice and Arabic words in English text by the Arabic voice; the runs of one sentence are queued together so there is no extra pause at the switch (can be turned off).
- **Arabic vowel marks for listening (Claude):** an optional, separate copy of each Arabic translation with full tashkeel (incl. shadda, tanween, case endings). It is used only if its letters are *exactly* the translation's letters (checked character by character), so no word can change; it is shown read-only under the translation ("by Claude — check it") and becomes invalid when the translation is edited.
- **Audio bar (since 13 Oct 2026, rebuilt with the reading modes):** a full-width bar along the bottom of the reader — it never floats over the text column, and the side panels stop at its top edge (also at the end of the paper, where it rises). Previous paragraph · **play/pause** · next paragraph · stop; what is being read ("Reading ¶12 · Original") with its section; the **version** read (the same choice as above the paper); speed; **Voices & accents**; **More settings** (a pop-up above the bar, closed by ×, Escape or a tap elsewhere): play only the selection / paragraph / section, from the start, previous / replay / next **sentence**, the voices with their quality, volume and notes. A ˅ button makes the bar smaller (play and the current paragraph only). When nothing is loaded, previous / next paragraph move the selection, so Play starts there. A thin line along its top shows the progress.
- **What you see is what you hear (13 Oct 2026, after the owner found that Simple English kept reading the original; versions separated the same day at her request):** the version shown above the paper decides what is read, and only that version — *Original* reads the original, *Simple English* reads only the simple versions (no "In simple words" before each one), *Arabic* reads only the Arabic translations. A paragraph without that version has its original read, and the status says why ("Reading ¶3 · Original (no Arabic translation yet)"); the settings say how many paragraphs are affected. The player names the version it reads ("Read aloud · Arabic"); choosing a version in Settings changes the paper too, and changing it while reading continues in the new version from the same paragraph. The big Play button starts at the **selected paragraph** ("Play from ¶5"; "from the beginning" for ¶1). The old combined view *Original + Arabic* is now *Arabic*, with the original one click away.
- **Listening to one part never loses your place:** only the main reading (from a paragraph onwards) has a bookmark. Listening to one paragraph's Original, Simple or Arabic, a section, a selection or a Claude answer never moves or deletes it, so Continue afterwards resumes the main reading where it paused.
- **Controls:** Play all / Pause / Continue / Stop / From the start; previous sentence, **replay sentence**, next sentence; Play only: **Selection** (select text in the paper, including in the simple/Arabic boxes), **Paragraph**, **Section** (also a Section button on every paragraph); speed 0.75 · 0.85 · 1.0 · 1.15 · 1.25 · 1.5 (the voice's own rate, no pitch change); volume; natural pauses between paragraphs and after headings; the section heading is said when a new section starts (can be turned off).
- **Pause keeps the exact word; Continue resumes there** — also after leaving the tab, switching paper or reloading (a bookmark per paper in `S.reader.marks`). Reading a selection or a preview never moves the bookmark. All voice settings are saved (`S.reader`: enAccent, voiceEn, arRegion, voiceAr, gender, rate, volume, mixed, pauses, headings, cites, lexicon).
- Highlights the current sentence in the original text. Figures are never read. The professor-questions step (4.2) uses the same voices and pronunciation.

**Ask Claude:** a chat per paragraph and one for the whole paper. Suggested prompts include *Explain this more simply*, *Give me an everyday example* and *اشرح هذه الفقرة بالعربية*. Claude must answer from the paper and separate general knowledge from what the paper says. Answers stream, can be stopped, can be listened to and copied, and are saved.

**Arabic translation:** Claude translates each paragraph faithfully into Modern Standard Arabic (with the English technical term in brackets the first time), or the user pastes their own. Shown right-to-left.

**Use in Critique:** attaches the paper's text to the AAU critique for evidence search.

### 5.4 Critique Studio (step 2.3)

### 5.4b Where Did This Come From? — Source Evidence Mapping (step 2.4)

- **Documents:** the same document set as Part 4 (paper, critique, slides). ## 7. Known limitations

- **Scanned PDFs** (images of pages) have no text: use *Paste text*. OCR is not built in.
- **Paragraph detection** is heuristic. In papers that separate paragraphs with a blank space (not an indent), a figure placed exactly where a sentence ends with a short line is ambiguous, so the text stays as two blocks (no words lost).
- **Figure cropping** is automatic and can include a stray line; the full page is always sent to Claude as well. Captions must start with "Fig. N." / "Figure N:" / "TABLE N".
- **PDF page numbers** are the PDF's own pages, not the journal's printed numbers.
- **Voices** depend on the device and browser; ScholarPath cannot make a robotic voice natural, only choose the best one available and tell the user how to get better ones. Natural voices in Edge need an internet connection. Some voices don't report word positions, so Continue then restarts at the sentence. Real audio quality (naturalness, accents, Arabic fluency) can only be judged by listening on the owner's devices — the automated tests use a stand-in speech engine.
- **No premium voice service:** neural cloud services (Azure, Google Cloud, ElevenLabs, OpenAI) would need an API key kept on a server, cost money per character, and may not be reachable from the claude.ai page. Not integrated (the owner asked for pricing and setup first).
- **Dialects:** no Arabic voice speaks a dialect from Standard Arabic text; regional voices are offered as speakers' accents only. Mixed-language switching depends on the engine honouring queued utterances; a very short switch (one Arabic word such as "و" between English terms) is still a separate utterance.
- **AI features** need the published claude.ai page and use the viewer's Claude account. They are not available in the plain file.
- **Pictures and data** are stored in the browser only. The JSON backup excludes the pictures and the original Word/PowerPoint files of Part 4.
- **Word and PowerPoint (Part 4):** reading compressed files needs `DecompressionStream` (Chrome/Edge 80+, Safari 16.4+, Firefox 113+). Text in pictures, SmartArt and embedded objects is not read. A correction is made only when the old words sit inside one paragraph (not across a line break or two text boxes); otherwise it is marked "do this by hand". Chart data is read but not changed. Corrected copies are stored uncompressed, so they are larger than the original (they open normally).
- **Evidence mapping:** precision depends on how well the PDF's text was extracted; a quotation that the PDF splits differently (e.g. across a page) may not match word for word and is then treated as not verified (the safe side). Claude's classification (direct / paraphrase / interpretation) is a judgement to check; only the quotations and locations are verified mechanically. Papers read before 12 Oct 2026 have no stored PDF, so the PDF-page view is unavailable for them (re-upload to enable it). Printed page numbers are shown only when the student sets the first printed page.
- **Voice typing** in the mock professor uses the browser's speech recognition (in Chrome an online service). It may be blocked inside the claude.ai page; typing always works.
- **Professor questions** take several Claude calls (one analysis, then two critique sections or eight slides per call); a long critique takes a few minutes. Regenerating replaces Claude's questions (her own questions and the practice log stay), so preparation statuses start again for the new questions.
- **Verification limits:** very long documents are cut before they are sent to Claude (the prompt says so, and those parts become "Not Verified"). External references can only be checked against the paper, so they are "Not Verified" unless the paper cites them. The automatic number check is a pointer, not proof: a number found in the paper may still be used with a different meaning.
